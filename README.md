# 株式会社EARTHIA工業

福井・北陸の清掃会社、EARTHIA工業のコーポレートサイト。
ビルド不要の静的サイトで、Vercel から配信しています。

## 構成

```
index.html            トップページ（HTML / CSS / JS を1ファイルに同梱）
recruit.html          採用情報（同じく1ファイル完結・スクリプトなし）
pest.html             害虫駆除・防除 定期管理プラン（チラシの専用ページ）
images/               ビフォーアフター写真（ba1–6）とロゴ
                      mark-earthia.png      ナビとフッターのシンボル（白を透過）
                      logo-relifeworks.jpg  Re:Life Works（黒地のまま）
                      logo-koesa.png        KOESA のバッジ（円形に切り抜き済み）
favicon.svg           E モノグラムのファビコン
apple-touch-icon.png  iOS ホーム画面用（180px、SVG 非対応のため別途）
vercel.json           静的配信の指定（フレームワークなし・ルートを配信）
.nojekyll             GitHub Pages に切り替えた場合の Jekyll 回避
```

ヒーローの動画8本は Higgsfield CDN（CloudFront）から直接読み込むため、
リポジトリには含まれません。

## ページの中身

- **ヒーロー** — 8本の動画を順に流すドラマ仕立てのシーケンス（各クリップが終わると次へ）。
  「困っている店主のもとにプロ集団が来て、店を生まれ変わらせる」という筋立てで、
  各シーンに日本語のメッセージを1つずつ重ねています。
- **イントロ** — ステートメント。
- **事業内容** — 清掃部門 Re:Life Works と工業部門 EARTHIA工業をタブで切り替えます。
  清掃側の6サービスは料金つきで、`<details>` で開くと内容が読めます。
  料金と説明文はチラシの記載どおりです。変更する時はチラシ側も揃えてください。
  **害虫駆除・防除 定期管理プラン**は専用チラシの転記で、カードの中に
  「毎月1回プラン（年間 42,000円）」「3ヶ月に1回プラン（年間 22,000円）」の切り替えが
  あります。切り替えは部門タブと同じ `[role=tablist]` の仕組みで、スクリプトが
  ページ上のすべての tablist を面倒みます。スクリプトなしでは両プランが縦に並びます。
  安心保証・3つの理由・対応施設もチラシどおりです。
  同じチラシの事業内容欄にある**リフォーム・塗装は取りやめになった**とのことで、
  サイトには載せていません。チラシから転記しないでください。
  **営業時間は「受付 9:00〜18:00（年中無休）／現場対応は24時間」**で確定です。
  約束事リスト・お問い合わせの電話カード・会社概要の3箇所に入っています。
  「24時間対応」とだけ書くと受付も24時間に読めるので、必ず「現場対応」と付けてください。

  **サービスの出し入れ**は、`<details class="svc">` に `hidden` を付けるだけです。
  付けると消え、外すと戻ります。削除しないでください（文面と料金が失われます）。
  工業側は定款どおりの項目名なので説明を付けず一覧です。
  両パネルとも HTML では表示状態で置き、片方を隠すのはスクリプト側です。
  JavaScript が動かない環境でも、どちらの事業内容も消えません。
  ヒーローと実績は Re：Life Works の仕事です。
- **契約実績（グラフ）** — 月別の新規ご契約社数を棒グラフ、累計を折れ線で重ねます。
  **数字の在処は `#chartData` の表ひとつだけです。**
  スクリプトはその表を読んで SVG を描き、描けたら表を読み上げ用に隠します。
  月を足すときは `<tr><th>3ヶ月目</th><td>18</td></tr>` を1行足すだけで、
  累計も見出しの「◯◯社以上」もグラフも自動で追従します。
  JavaScript が動かない環境では表がそのまま残るので、数字は必ず読めます。
  現在の値は**1ヶ月目 20社・2ヶ月目 30社（累計50社）**で、社長から聞き取った実数です。
- **実績（ビフォーアフター）** — グリストラップ清掃6件。
  ハンドルをドラッグして施工前後を比較できます（マウス／タッチ対応）。
- **会社概要** — 商号・代表者・所在地・連絡先。
- **料金のご相談** — 「他社様で高いと感じた場合、一度ご相談ください。」の一枚。
  LINE と電話への導線を持たせています。
- **お問い合わせ** — 電話は `tel:` なのでスマホからそのまま発信できます。

### 採用情報（recruit.html）

トップとは別ページです。上に暗い映像がないので、ページ全体を最初から
`:root` で明るい配色にしてあります（トップの `.daylight` と同じ値）。
クラス名もトップと揃えてあるので、片方で直した見た目はもう片方へそのまま移せます。

**募集要項は、決まっていない条件を書かない方針で作っています。**
雇用形態・契約期間・給与・勤務時間・休日・待遇は「勤務条件」1行にまとめ、
面談時に労働条件通知書で明示する旨を添えてあります。
条件が固まったら、表の中の HTML コメントに置き換え用の6行を用意してあるので
それと差し替えてください。職業安定法上、募集にあたっては
業務内容・契約期間・就業場所・労働時間・賃金・社会保険の加入状況の明示が
求められるため、**求人媒体に出す前には必ず埋めてください。**

### 害虫駆除 定期管理プラン（pest.html）

チラシを大きく見せる専用ページです。共通部分（トークン・ナビ・パネル・ボタン・フッター）は
`recruit.html` と同じ CSS を切り出して使っているので、直すときは両方揃えてください。
2プランはここでは切り替えではなく**横並びの比較**です（スマホでは縦に積みます）。
トップページからは、清掃部門パネル先頭の帯と、定期管理プランのカード末尾のボタンで来られます。
ナビには入れていません。6項目でスマホ幅ちょうどなので、7つ目は入りません。

### KOESA のクレジットの位置

「一番端で大丈夫」とのことで、トップは映像の左下隅（`left/bottom: 1rem`）、
採用ページと害虫駆除ページはフッターの右端（`.site-foot__sig{text-align:right}`）です。
著作権表記と同じ行に置くとスマホで重なるため、独立した行にしています。

## 配色

ヒーローは暗いまま、その下は明るい昼のテーマです。切り替えは `.daylight` ラッパーで、
中のセクションは同じ CSS のまま、カラートークンだけが反転します。
背景の空は `.sky`（`position:fixed`）で、CSS グラデーションを土台に写真を重ねています。
**写真が落ちてきても、落ちてこなくても空に見える**構成です。

ナビのバーはゴールドです。単色ではなく `--gold-lit → pale → mid → deep` の4段で、
上端に白1pxの照り、下端に金の打ち出し線（`::before` / `::after`）を入れています。
**金は1色で塗るとマスタードに見えます。**面の中の明暗の流れと two hairlines が、
金箔とただの黄色い矩形を分けています。文字は濃紺のままで、実測コントラストは 11.7〜15.7。
バーは下端まで不透明です。透けさせると、その時々のクリップの絵の上に文字が乗って読めません。

ナビの現在地と hover は、金の上に青いボタンを置くのではなく、**濃紺で塗って文字を金で抜きます**。

スマホのナビは6項目あるので `justify-content:safe center` を使っています。
**あふれた flex 行に素の `center` を使うと、先頭の項目がスクロール範囲の外へ押し出されて
永久に届かなくなります。**直前の `flex-start` は `safe` を解さない環境向けの受け皿です。

`#soundBtn` `.koesa-sig` `#progressBar` はヒーローの付属物なので、ヒーロー内に
`position:absolute` で置いています。`fixed` にすると明るいセクションの上に薄い色のまま
浮いてしまい、読めなくなります。

## ロゴ

EARTHIA工業はシンボルだけを使います（白背景は透過済み）。ロゴに含まれる社名は、
ナビにもフッターにもテキストで入っているため重複し、小さく置くと判読もできません。

Re:Life Works のロゴは銀と白の字で黒地に描かれているため、**明るいパネルには直接置けません**。
`.brand-band` という濃色の帯を用意し、その上に載せています。

KOESA のクレジット（`.koesa-sig`）は、KOESA のロゴバッジ＋筆記体の "Koesa"＋Instagram の
グリフで、**全体が KOESA の Instagram へのボタン**です。トップはヒーロー左下、
採用ページはフッターに置き、白地では金を落としてブロンズ（`#8a6a22`）にしています。

`images/logo-koesa.png` は支給されたロゴを**画像ファイルの時点で円形に切り抜いた**ものです
（320px・透過PNG・34KB）。元は正方形のスクリーンショットで、四隅の背景と
右下に写り込んだ iOS のテキスト認識ボタンが入っていました。内接円で抜くと
バッジのリング状の文字は全て残り、その2つだけが落ちます。CSS の `border-radius` だけに
頼らないのは、どの表示サイズでも四隅が出ないようにするためです。
**バッジはほぼ全面が青のグラデーションなので、減色するとバンディングが出ます。**
192色＋Floyd–Steinberg ディザで抑えてあります。

リンク先は `https://www.instagram.com/koesa_solutions_studio/` です。
支給された URL には `stkn=…` と `utm_source=qr` が付いていましたが、**どちらも外してあります**。
`stkn` は QR から生成された共有リンクに紐づく共有トークン、`utm_source=qr` は QR 経由の
計測用パラメータで、サイトに焼き込むものではありません。プロフィールの正規 URL だけを置いています。

筆記体の "Koesa" は**フォントではなく、SVG の輪郭データ**です（`.koesa-sig__name` は `<svg>`）。
Great Vibes（SIL OFL 1.1）で組んだ文字を HarfBuzz で整形（連綿の字形と字間を適用）し、
fontTools でパスに起こしました。約5KB をインラインで両ファイルに埋め込んでいます。
最初はウェブフォントで出していましたが、**実機で筆記体にならない**と報告がありました。
アプリ内ブラウザや広告ブロッカーが fonts.gstatic.com を落とす、Android の `cursive` が
筆記体でない、など端末側の事情はサイトから制御できません。絵にしてしまえば必ず同じに出ます。
文字を変えるときは `scratchpad` の `outline.py`（HarfBuzz + fontTools）で再生成してください。

## 実装メモ

- **文字は焼き込まない** — メッセージはすべて HTML のオーバーレイです。
  以前は映像に文字が焼き込まれていて、縦画面で両端が切れるうえ、
  オーバーレイと二重に出ていました。素材から文字を外したことで両方が解消しています。
- **クリップの読み込み** — 先頭以外は `preload="none"` で置き、`warmNext()` が
  再生順に**1本ずつ**読み込みます。次の1本は前の1本がバッファできてから始めるので、
  同時に走るダウンロードは常に1本だけです。8本を一斉に読むと回線が分割されて
  表示中のクリップが息切れし、逆に「1本先だけ・直前に読む」では遅い回線で間に合いません。
- **引き継ぎ** — クリップが終わる `CROSSFADE` ミリ秒前に `timeupdate` が引き継ぎを始め、
  前のクリップが**まだ再生中のまま**次と重ねてクロスフェードします。継ぎ目で両方が動いている
  ので、静止フレームが挟まりません。`CROSSFADE` は `.hero__slide` の
  `transition:opacity` と同じ値にしてください。ずれると絵が切り替わり切る前後に隙間が出ます。
  前のクリップを止めるのはフェードが終わってからです。
  実測: 継ぎ目の178サンプル中、何も動いていない瞬間は0。
- **シーンの切り替え** — 固定タイマーではなく、クリップの `ended` で次に渡します。
  そのため `loop` は付けられません（loop 中は `ended` が発火しない）。
  止まったクリップで停滞しないよう、9秒のウォッチドッグを併用しています。
  これは `timeupdate` のたびに張り直すので、バッファ中で「進んではいる」クリップは
  打ち切られません。読み込みに失敗したクリップは `error` で即座に次へ送ります。
  最初のスライドには `active` が必要です。付け忘れるとシーン1が一度も表示されません。
- **再生位置の巻き戻し（スマホでシーンが一瞬で飛ぶ原因）** — スマホはメモリが逼迫すると
  バッファ済みのクリップを破棄し、**前回停止した位置に再生ヘッドを残したまま**
  返してきます。2周目のシーンが終端間際から再開すると、最初の `timeupdate` で
  「残り `CROSSFADE` 未満」が成立して即座に引き継ぎが走り、シーンが一瞬で飛びます。
  PC は8本すべてをメモリに保持できるので再現しません。対策は3段構えです。
  1. `currentTime = 0` は `readyState < 1`（メタデータ未取得）では**黙って捨てられる**ので、
     `loadedmetadata` を待って `settle()` で巻き戻し直します。
  2. それでも先頭に戻らなければ `load()` で読み込み直します（1シーンにつき1回）。
  3. 最後の砦が `MIN_DWELL`（3秒）。この時間に満たない引き継ぎ要求は**破棄せず繰り延べる**ので、
     本当に短いクリップも出番を失いません。
  実測（6秒クリップ・iPhone 13 エミュレート・CPU 4倍・低速回線）では、
  対策前は全シーンが 1.59 秒に潰れて 60 秒間に26回切り替わり、対策後は 3.00 秒を下回らず
  15回に収まりました。正常時は PC・スマホとも 4.78 秒で変化ありません。
- **Sound On でセリフの最後が切れる（iPhone）** — iPhone は「音の出る動画は同時に1本」なので、
  クロスフェードで次のクリップが音付きで走り出した瞬間、前のクリップを止めてしまいます。
  シーン7のおじさんのセリフが1.4秒早く切れていたのはこれです。いまは次のクリップを
  **ミュートでフェードイン**させ、前が止まってから `muted = !soundOn` に戻しています。
  代わりに各シーンの冒頭1.4秒は無音になりますが、セリフは冒頭にないので実害はありません。
- **スマホで動画がカクつく** — 原因は2つでした。`.hero__slide video` の `filter:brightness()`は
  再生中の**全フレーム**に毎回かかるので、スマホの GPU では間に合いません。`(pointer:coarse)` では
  外しています。もう1つは8枚のスライド全部に付けていた `will-change:opacity` で、動画8本ぶんの
  合成レイヤーを常に確保させるためメモリが逼迫し、クリップの破棄（上の「再生位置の巻き戻し」の
  引き金）も招いていました。外しても opacity の transition は問題なく動きます。
- **モバイルの動画 autoplay** — `muted` + `playsinline` + `webkit-playsinline` で
  iOS のインライン再生を許可し、さらに最初の `touchstart` / `click` で
  再生をかけ直します。このとき**止まっているクリップだけ**を対象にします。
  スマホの最初のタッチはたいていスクロールの開始なので、再生中のシーンまで
  `startClip()` に通すと冒頭のフレームに巻き戻ってしまいます。
- **Sound On** — 右下のトグルで動画をアンミュートします。
  ミュート状態は `soundOn` が唯一の情報源で、`manageMedia()` はシーン切替のたびに
  `vid.muted = !soundOn` を適用します。ここを無条件に `true` にすると
  Sound On が次のシーンで解除されてしまうため注意してください。
- **AI表記** — ヒーローは生成AIのイメージビデオなので、映像の上に常時注記を出し、
  フッターに正式な文言を置いています。実在のスタッフと現場に見える映像なので、
  表記が無いと誤認されます。なお**ビフォーアフター写真は実際の施工写真**です。
  ひとまとめに「フィクション」と書くと本物の実績まで作り物に見えるため、
  文言では必ず分けてください。
- **アンカーと固定ナビ** — ナビが `position:fixed` なので、リンク先の節には
  `scroll-margin-top` が要ります。無いと見出しがナビの下に潜ります。
- **日本語の折返し** — 日本語はどの文字の間でも改行されるので、狭い画面では
  語の途中で切れます。読点で区切った各句を `.clause`（inline-block）に入れ、
  句と句の間でしか改行できないようにしています。ヒーローのコピーは JS が流し込むため
  `setCopy()` が同じ処理をします。コピーを追加するときは読点を目安に区切ってください。
- **文字の太さ** — 見出しは Noto Sans JP の 900、本文寄りは 700/500 です。
  使うウェイトは Google Fonts のリクエストにも入れてください。入っていないと
  ブラウザが合成太字を作り、日本語のグリフが潰れます。
- **動画の明るさ** — `--video-lift` で持ち上げています。この1つの数値だけで調整でき、
  1 なら素材そのままです。`brightness()` は乗算なので黒は黒のまま残ります。
- **ビフォーアフターの色補正** — 写真は彩度を落とし（`saturate` 0.25–0.3）、
  `.ba-slider::before` のネイビーのグラデーションで青寄りに寄せています。
- **社名** — ロゴは英語の `EARTHIA`、その下に正式名称の `株式会社EARTHIA工業`。
  英語の見た目を保ちつつ、取引先が実在を確認できるようにしています。
